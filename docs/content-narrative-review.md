# 个人网站叙事审评与重构

日期：2026-09-05。对象：潜在合作方第一次访问网站的阅读与判断过程。

## 核心定位

杨朋翰是一个能独立判断、重新定义问题，并组织现有工具与专业资源把事情推进的问题解决专家。心理学和一线研究是判断的基础；研究设备、代码、AI、团队协作是可选手段。

“独立”描述工作能力与判断，不推断为自由职业或独立签约。现任 Noldus 中国咨询与业务拓展负责人、商业咨询通过 Noldus 交付的事实保留。

## 审评发现

| 现有内容与位置 | 合作方读到的障碍 | 重构决定 |
| --- | --- | --- |
| 首页“我测量真实行为，并把方法做成系统” | 只知道手段，不知道遇到什么困难该找你 | 首屏交代问题解决定位；紧接三个可对号入座的场景 |
| 首页六个精选项目，前三项全是 AI，其中两项为原型 | 容易把你理解成 AI 工具搭建者；成熟经验被淹没 | 精选金融、医疗器械、机器人三个案例，分别证明分析、重构需求、低成本验证 |
| 工作页按 system / study 分类 | 这是作者的归档方式，读者仍要自己找入口 | 改成代表案例、更多已交付经验、AI 工作与实验；保留状态标识 |
| 大量“系统、能力、证据链、放大、沉淀” | 抽象结论重复，无法判断实际动作 | 案例写清最初问题、我的判断、做法、交付与尚未验证的部分 |
| 首页重复原型、数字墙与六场演讲 | 阅读主线反复中断 | 数字回到对应案例；原型留在工作页；演讲移到关于页 |
| 关于页七项项目记录、技能词表、原则和边界 | 像第二份项目索引，仍然看不到合作体验 | 保留经历，增加“合作时你会看到的习惯”，删除重复项目墙 |
| 联系区先讲签约渠道，并承诺两天回复 | 访客不知道第一封信怎么写；回复时效无依据 | 先提示目标、卡点、已有尝试，再说明联系与交付渠道 |
| AI 案例“生产级”“运行一年”，三遍编码“允许漏检” | 前者缺验证且与 2026 年起步时间冲突；后者后续仅分析候选段，无法自动找回漏检 | 降低未经验证的结果表述，修正时间与方法逻辑 |
| 医疗案例中虚构的临床操作表、平台全流程与首个等宣传 | 样例可能被误认作真实项目证据，平台成果与个人贡献混杂 | 删除虚构临床记录和未经本轮核实的领先性宣传，保留明确角色与已有方法事实 |

## 阅读路径与页面职责

1. 首页：我是谁 → 什么情况下找我 → 三个案例 → 怎样合作 → 了解我 → 三篇笔记 → 联系。
2. 案例页：快速判断相似度。每项先讲具体问题，接我的选择和可说明的产出。AI 实验独立成组。
3. 方法页：解释项目怎样开始、如何选择手段、如何检查与交接。技术细节按需展开。
4. 关于页：讲工作经历和个人判断习惯。履历与公开演讲作为补充证据。
5. 笔记页：呈现推理与尚未确定的判断，不再复制一套个人品牌宣言。

## 文案与事实标准

- 中文采用本人解释一个实际问题的口吻，英文同步改写，不逐字翻译口号。
- 不新增客户、业绩、节省时间、性格逸事、服务承诺。已有经历来自仓库内容，本轮不等于重新核验原始档案。
- 86 个问题、60 次测试与访谈等保留原有统计口径；交付物不写成已证实的业务成效。
- 原型数量、速度目标与运行状态分开。删除不必要且易过时的模块/文档数量堆砌。
- 公司业务、团队产出与个人职责分开表述。未经授权的客户细节继续保密。
- 性格通过“先问什么、如何分歧、怎样面对未知”呈现，不虚构故事或自称与众不同。

## 验收

检查中英文主线一致、案例入口与状态、旧链接、移动端长标题、页面可访问性。运行项目 lint、Astro 检查、现有测试、构建与浏览器审计。不得将构建通过表述为文案转化率已经验证。
